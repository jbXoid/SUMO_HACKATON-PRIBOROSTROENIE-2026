# Sumo_mini
Programs for ROBOTS Sumo mini

Что доделать:
1. Режим старта Start_Fast;
2. Режим "Периметр";
3. Дефайны выбора ринга (черный или белый);
4. Проработать режим ухода от атаки в бок. Подобрать настройки
5. В процессе ТОРНАДО, если происходит обнаружение цели и переход в АТАКУ, проходит слишком много времени и робот
	успевает проскачить цель. В режиме АТАКА происходит переключение в режим доворота к цели или резкого разворота.
	РЕШЕНИЕ:
	- Попробовать делать переход из "ТОРНАДО" (при обнаружении цели двумя передними датчиками) сразу в "ДОВОРОТ К ЦЕЛИ"
6. Подобрать новые параметры дальности цели в связи с найденной ошибкой поиска среднего арифметического
7. Продумать вопрос работы АЦП через прерывания

Наблюдения:
- Интересный эффект при скоростном старте робота FK35. Если размещать
	неподвижную цель слева или справа от линии входа в ринг, робот
	после входа по прямой развернётся в соответствующую сторону к
	цели.
  Это происходит случайным образом. Проходя мимо цели, в переменной
  ADCH_n сохраняется значение АЦП в момент прохода мимо цели и не
  успевает обновиться новым значением прежде чем выйдет время
  T_START_FAST_IGNORE

Ошибка поиска среднего арифметического
---------------------------------------------------------------------
- Сумма из 5 элементов делилась поразрядным сдвигом вправо на 2.
	Ошибка в том, что так можно делить только на степень двойки.
	Ср.арифм. 8ми элементов нужно сдвинуть на 3 вправо.
- Вместо макс. знач. 153 -> (153*5)>>2, получалось 191

Среднее арифметическое
---------------------------------------------------------------------
- Данные АЦП сохраняются в массив Buff
- Сохраняется 8 значений каждую мс, затем суммируются
- Поразрядным сдвигом вправо на 3 делается деление на 8
-> Т.к. приходится переключать вход АЦП для каждого канала, нет
	непрерывного потока данных. В таком случае не получится вычислять
	простое скользящее среднее (SMA).
